Booqable Rental Theme · case study

Booqable rentals, without the Booqable widget.

A block theme and companion plugin for a home-staging rental business. The catalog, stock checks and checkout call the Booqable API v4 from the server, so the storefront is plain WordPress and the access token never reaches a browser.

A staging business rents furniture by the date, and its inventory lives in Booqable.

A real-estate staging company needs a site that looks as considered as the homes it stages, shows what can be rented, and takes bookings online. Its stock, prices and orders are already managed in Booqable.

Booqable's own WordPress route is a plugin that drops in shortcodes and a client-side widget script. The site cannot style that widget like the rest of the page, and every booking step runs inside code the site does not control.

What finished looks like, stated so it can be checked:

  • Visitors browse live inventory by category, and a category renamed in Booqable needs no change in WordPress.
  • A visitor picks dates, adds items and checks out without leaving the site.
  • The Booqable access token never reaches the browser.
  • Switching the theme leaves the rental features working.

The staging business is fictional and the build is self-initiated. Photos on the demo site are placeholders from picsum.photos, which the screenshots below show as they are.

The storefront is WordPress; Booqable is only ever called from the server.

Integration

Call the API instead of embedding the widget

The official Booqable plugin was removed. A single Client class talks to API v4 with a bearer token and maps each JSON:API response down to the few fields a block needs, so no raw envelope ever reaches a template.

API v4JSON:APIClient.php

Security

Keep the token on the server

Only the Client class reads the token. The browser sees public booqable-core/v1 routes that return filtered data, and the settings screen never shows the saved token again.

Structure

Theme renders, plugin works

API client, caches, blocks, cart and checkout live in the plugin. Even the cart button is printed by the plugin, so editing the theme header cannot remove it.

Cart

Keep the cart in the browser until checkout

Adding, changing quantities and picking dates write to localStorage with no request. Booqable hears about the order once, at checkout.

Payment

Manual payment, because the gateway is not offered

Stripe does not support this Booqable account's country. Checkout reserves the order, shows bank transfer or QRIS instructions, and a cron job cancels orders left unpaid past the hold window.

What one rental does, from the first click to a reserved order.

The steps run on every booking. The table beside them lists one decision per layer and what it buys.

  1. Fill the cart in the browserBook, quantity and date changes are reads and writes of localStorage. No request leaves the page.
  2. Check stock in the backgroundAfter an item is added or the dates change, GET booqable-core/v1/availability fetches the available count and clamps the quantity. It changes nothing in Booqable.
  3. Send the whole cart oncePOST booqable-core/v1/checkout carries name, email, phone, dates and lines in a single request.
  4. Create the order and book every lineIndependent calls go out together: the order and the customer lookup first, then every line through order_fulfillments. Any failure cancels the partial order.
  5. Attach the customer and reserveThe customer is found by email or created, attached to the order, and the order moves from new to reserved, which is what makes it visible to staff.
  6. Pay, or release the stockThe confirmation shows the order number, Booqable's total and the payment instructions. Orders still unpaid after the hold window (24 hours by default) are cancelled by WP-Cron.

booqable-rental-theme-core/includes/class-client.php

// Client::get(). Only this class ever reads the token.
$slug = $this->get_company_slug();
$url  = sprintf( 'https://%s.booqable.com/api/4/%s', $slug, ltrim( $path, '/' ) );

$response = wp_remote_get( $url, array(
    'timeout' => 10,
    'headers' => array(
        'Authorization' => 'Bearer ' . $this->get_access_token(),
        'Accept'        => 'application/json',
    ),
) );

booqable-rental-theme-core/includes/class-checkout.php

// Every line only depends on the order, so they are booked together.
$phase2 = $this->client->request_multiple( $phase2_calls );

foreach ( $lines as $index => $line ) {
    $booked = $this->client->extract_line( $phase2[ 'line_' . $index ] );
    if ( is_wp_error( $booked ) ) {
        // never leave a partial, customer-less order behind
        $this->client->cancel_order( $order_id, 'new' );
        return $booked;
    }
